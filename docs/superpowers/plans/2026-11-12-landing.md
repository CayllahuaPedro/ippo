# Ippo Landing Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve a bilingual waitlist landing page at `/` (EN) and `/es` (ES) inside the existing Next.js app, with a live reader demo, while the app routes keep their shell.

**Architecture:** Three root layouts via route groups, `(app)`, `(en)` and `(es)`, share one `RootDocument` (fonts, theme boot script, `<html lang>`). All landing code lives in a new `features/landing` feature (pure `model/`, `.ts` hooks, presentational `components/`), talking to `reader`, `discover` and `tutor` only through their barrels. The waitlist goes through one seam that refuses honestly in production.

**Tech Stack:** Next.js 15.5 App Router, React 19, Tailwind v4 (tokens in `src/app/globals.css`), Vitest + jsdom + @testing-library/react, dependency-cruiser.

**Spec:** `docs/superpowers/specs/2026-11-12-landing-design.md`

All paths below are relative to `frontend/`.

## Global Constraints

- Single CTA everywhere: join the waitlist. No sign-in, no extension download, no pricing.
- English at `/`, Spanish at `/es`; Spanish is neutral, uses "tú".
- `hreflang` alternates: `en` → `/`, `es` → `/es`, `x-default` → `/`.
- No invented users, testimonials, metrics or learner data. Never promise fluency or outcomes.
- Never name other products (Refold, MIA, Migaku…). Say "the immersion community". Krashen may be named.
- No mascots, illustrations, icon grids or extra colour: ink `#1b1547`, violet accent `#6b5ce7` as the only accent, 1px hairlines, Figtree + Zen Kaku Gothic New at 400/500. Use existing tokens (`bg-ground`, `text-ink`, `text-muted`, `text-faint`, `border-hairline`, `bg-accent`, `bg-tint`, `font-jp`…), never raw hex.
- Wordmark is the plain text "Ippo".
- No new runtime dependencies.
- Hooks live in `.ts` files, never `.tsx`. Conditional classes use `cn(...)`, never template literals. No redundant comments.
- Feature boundaries: `src/app/` and other features import `features/landing` only via `src/features/landing/index.ts`; `model/` imports no React, hooks or components.
- WCAG AA contrast, body text ≥ 14px, 16px side gutter on phones, no horizontal scroll.
- Every task ends green on `npm run check` (typecheck + depcruise + vitest) run from `frontend/`.
- Conventional commits, no AI attribution lines.

## Review Focus

1. **Phone-width demo** (≤ 400px): the popup must stay inside the viewport and usable; `popupPosition` assumes a 372px popup and would clamp negative. → Task 4 renders the popup as a static block under the passage below `lg`, and tests the state change without layout.
2. **Keyboard use of the demo**: Escape closes the popup and focus returns to the word that opened it. → Task 4 test `returns focus to the word on Escape`.
3. **Whitespace/case in the email** (`"  Ana@Mail.com "`): accepted and trimmed; `"ana@mail"` and `""` rejected without calling the seam. → Task 3 tests.
4. **Double submit** while a request is in flight: the seam is called once. → Task 3 test `ignores a second submit while submitting`.
5. **Missing Spanish string**: every EN key exists and is non-empty in ES. → Task 2 test `es copy has the same shape as en`.
